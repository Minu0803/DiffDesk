# 빈 화면 안내와 시작 속도 개선 — 2026-10-07

빈 화면 안내를 툴바 아래 비교 결과 밴드로 옮겼다. 가운데 분할선과 겹치던 편집기 위 안내와 해당 CSS를 제거했다. 양쪽 문서가 모두 비었을 때만 안내를 표시하고, 내용을 불러오면 비교 결과가 그 자리를 사용한다.

빈 모델의 초기 비교가 이벤트 구독 전에 끝나면 `onDidUpdateDiff`를 놓쳐 “비교 계산 중…”이 계속 남았다. 이벤트를 연결한 뒤 현재 결과를 한 번 반영하도록 수정했다. 기존 모델 버전 검사를 유지해 이전 비동기 결과를 승인하지 않는다.

## 시작 속도와 배포

실측에서 지연의 대부분은 단일 EXE가 매번 앱 전체를 임시 폴더에 풀 때 발생했다. Monaco의 언어 서비스 제외 실험은 편집기 준비 시간을 유의미하게 줄이지 못해 적용하지 않았다. 기존 문법 강조와 편집 기능을 유지했다.

단일 EXE에 `portable.useZip: true`를 적용했다. 현재 electron-builder 25.1.8에서는 내장 7z 대신 NSIS의 zlib 해제 경로를 사용한다. 이 설정은 실행할 때마다 압축을 해제하는 구조 자체를 바꾸지는 않는다.

한 번 풀어 두고 바로 실행할 수 있는 `DiffDesk-fast-start.zip`을 기본 Windows 빌드 결과에 추가했다. ZIP을 원하는 폴더에 풀고 내부 `DiffDesk.exe`를 실행한다. EXE와 함께 제공되는 파일·폴더를 유지해야 한다.

### 같은 환경에서 각 3회 실행

| 배포본 | 시작부터 로드까지 추정 중간값 | 프로세스 종료까지 중간값 |
|---|---:|---:|
| 기존 단일 EXE | 6.566초 | 9.343초 |
| 개선 단일 EXE | 3.131초 | 5.850초 |
| 개선 폴더 실행본 | 0.804초 | 3.423초 |
| 실제 배포 ZIP을 풀어 실행 | 0.981초 | 3.611초 |

내장 QA는 `did-finish-load` 후 2.5초를 기다려 캡처한다. 시작부터 캡처 파일 생성까지의 시간에서 이 대기를 뺀 추정치이며, 전체 종료 시간에는 캡처 대기와 포터블 임시 폴더 정리가 포함된다. 순차 실행했고 다른 DiffDesk 인스턴스는 없었다. 운영 설정을 읽지만 QA 모드는 설정과 창 위치를 저장하지 않는다. Chromium의 정상 프로필·캐시는 공유한다.

개선 EXE의 첫 측정은 6.525초였고 다음 두 번은 3.131초와 3.128초였다. 첫 실행의 캐시·보안 검사 편차가 있으므로 첫 실행도 절반으로 빨라졌다고 해석하지 않는다. 빠른 시작을 우선하면 ZIP 버전을 권한다.

압축 방식 변경으로 EXE 크기는 기존 76,894,599바이트에서 118,928,748바이트로 늘었다. ZIP은 114,681,411바이트다.

## 검증

- 기존 자동 테스트 13개 통과, renderer/Electron TypeScript 검사와 프로덕션 빌드 통과.
- 초기 비교가 영원히 계산 중으로 남는 회귀 검증을 수정 전에 실패시킨 뒤 최종 빌드에서 통과시켰다.
- 최소 창 너비 944px의 실제 콘텐츠 영역에서 라이트와 Deep Dark 안내가 잘리지 않고 편집기를 가리지 않음을 확인했다.
- 격리된 네이티브 프로필에서 파일 드롭 → TypeScript 자동 감지·문법 강조 → 비교 → 부분 병합 → 대상 실행 취소 → 한 줄 보기 → 전체 지우기 → 안내 복귀, Ctrl+F 검색을 확인했다.
- 패키지 ASAR의 renderer/Electron 파일 101개를 최종 로컬 빌드와 비교해 불일치 0개, QA 실행 도구 포함 0개를 확인했다.
- ZIP 무결성 검사 통과, 배포 ZIP에서 직접 추출한 EXE를 3회 실행·캡처·종료했다.
- 독립 코드 검토에서 초기 결과의 버전 검사와 빈 상태 전환에 중요한 결함이 없음을 확인했다. 이전 캡처를 재사용해 잘못 성공할 수 있던 벤치마크는 실행마다 고유 캡처 폴더를 사용하도록 수정했다.

결과 PNG/JSON은 [검증 자료](2026-10-07-assets)에 있다. 변경은 커밋하지 않았다.

## 재현

빌드한 뒤 `node scripts/qa-startup.cjs current --check --smoke`로 격리된 시작·동작 QA를 실행한다. `DIFFDESK_STARTUP_MINIMUM=1`, `DIFFDESK_STARTUP_THEME=ink`로 최소 창과 다크 테마를 선택할 수 있다.

앱을 모두 닫은 뒤 `node scripts/qa-packaged-startup.cjs 실행파일경로 라벨`로 패키지 시작을 비교한다. 결과는 `build/startup-라벨.json`에 저장되고 매 실행의 PNG는 고유 캡처 폴더에 저장된다. 캡처가 없으면 기존 인스턴스에 전달되어 종료된 실행을 성공으로 계산하지 않는다.

이번 호스트의 Windows 패키징 도구 캐시는 macOS 심볼릭 링크를 만들지 못해 기본 해제에 실패했다. 다운로드된 도구에서 Windows 파일만 `build/electron-builder-cache`에 풀고 `ELECTRON_BUILDER_CACHE`를 그 경로로 지정해 패키징을 완료했다. 앱 설정이나 패키지 동작을 바꾸는 우회는 사용하지 않았다.
