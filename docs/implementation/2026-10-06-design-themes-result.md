승인된 부분 병합, 화면 디자인·모션, 테마 확장 계획을 구현했다. 변경은 작업 폴더에 있으며 커밋하지 않았다. 기존 리뷰 문서와 시안은 보존했다.

## 구현한 동작

- 부분 병합은 각 블록의 **[→][←]** 버튼으로 한 번에 적용한다. Monaco의 공개 레이아웃 옵션으로 가운데 **64px 전용 공간**을 확보해 버튼이 코드나 양쪽 라인 번호 위에 놓이지 않는다. 분할선을 움직이면 헤더와 버튼 공간도 함께 이동한다.
- 화면 밖에서 시작해 현재 화면까지 이어지는 긴 블록에도 버튼을 표시한다. 밀집한 블록은 버튼 위치를 정렬하며, 화면 가장자리의 한 블록 때문에 나머지 버튼까지 작아지는 문제를 방지했다.
- 입력과 병합 직후 이전 비교 결과의 버튼을 즉시 비활성화한다. 계산을 시작한 모델 버전을 확인해 늦게 도착한 이전 결과로 병합할 수 없게 했다. 같은 텍스트 모델을 유지하므로 Monaco의 실행 취소 기록을 보존한다.
- 부분 병합과 전체 복사는 실제로 변경된 쪽에 포커스를 둔다. 상태 표시줄의 실행 취소와 Ctrl+Z가 그 편집기에 적용된다. 병합 과정에서 별도의 커서 이동이나 강제 스크롤을 하지 않는다.
- 툴바·요약 띠·헤더·상태줄 높이를 각각 **42/32/30/26px**로 유지하면서 작은 브랜드 표시, 둥근 버튼, 색상 계층, 활성 편집기 표시를 정리했다.

## 모션

버튼의 클릭 영역은 고정하고 내부 표면만 움직인다. 누름 75ms에 0.96배, 복귀 240ms에 1.008배를 거쳐 원래 크기로 돌아온다. 빠른 클릭도 피드백이 보이며 연속 입력은 현재 위치에서 이어진다. hover는 140ms, 병합 대상 강조는 360ms, 적용 표시 유지 시간은 약 800ms다.

`prefers-reduced-motion`에서는 확대·축소와 이동 애니메이션을 줄인다. 이 수치는 승인 시안의 부드러운 반응을 구현한 값이며 iOS의 공식 모션 수치나 측정된 FPS를 의미하지 않는다.

## 테마

| 선택 항목 | 색감 | 편집기 배경 |
|---|---|---|
| Deep Dark | 네이비 기운을 줄인 무채색 블랙 | `#101010` |
| Navy Dark | 은은한 네이비 | `#171c27` |
| One Dark | 그래파이트와 부드러운 문법 색상 | `#282c34` |
| Dracula | 퍼플 중심의 선명한 포인트 | `#282a36` |
| Nord | 차가운 슬레이트와 파스텔 | `#2e3440` |
| GitHub Light | 밝은 배경과 명확한 대비 | `#ffffff` |

One Dark·Dracula·Nord·GitHub Light는 해당 색상 계열을 참고한 DiffDesk 프리셋이다. 기존 시스템·Light·Dark 선택도 유지했다. 프리셋은 기존 light/dark/system 설정과 분리해 저장하고, 잘못된 값은 기존 테마로 안전하게 되돌린다.

공유 팔레트를 앱 CSS, Monaco 문법·선택·변경 영역, Electron 창의 초기 배경에 연결했다. 설정을 미리 읽어 최초 배경도 선택한 프리셋에 맞춘다. 테마 선택 메뉴는 이름·색상 견본을 보여주고 화살표 키, Enter/Space, Escape, 현재 항목 재선택을 지원한다.

## 검증

- 자동 회귀 테스트 **13/13 통과**: 테마 호환·설정 재로드·Monaco 색상, 버튼 배치·화면 가장자리·긴 블록, 이전 비교 결과의 버전 판정과 연속 입력 계산 병합.
- renderer와 Electron TypeScript 검사 통과. renderer 프로덕션 빌드 및 Windows x64 휴대용 패키징 통과.
- 실제 Monaco 화면에서 양방향 부분 병합, 각 편집기 실행 취소, 전체 복사 후 대상 실행 취소, 테마 변경 후 실행 취소, 줄바꿈·공백 무시·보기 전환, 분할선 이동을 확인했다.
- 긴 블록 중간으로 스크롤한 상태에서도 병합 버튼이 표시됐다. 병합 전후 영향을 받지 않는 선택 영역과 보이는 줄의 위치를 비교해 유지되는 것을 확인했다. 긴 원본 줄의 끝 커서도 가운데 공간 밖에 유지됐다.
- Windows Electron의 Chromium 배율 **100/125/150%**에서 버튼이 모두 전용 공간 안에 있고 라인 번호와의 겹침은 **0**, 툴바 오른쪽 넘침은 **0**이었다. 최소 창 크기와 모션 감소에서도 같은 조건을 만족했다.
- Deep Dark와 GitHub Light의 격리된 네이티브 시작에서 저장된 프리셋, 초기 창 배경, 적용된 앱 배경이 일치했다. 사용자 운영 프로필은 변경하지 않았다.

배율은 Windows에서 Chromium의 device scale factor를 지정해 검증했다. 여러 모니터 사이를 이동하는 OS DPI 전환, 프레임 시간/FPS, 모든 언어·검색·진단 조합의 대비까지 측정한 것은 아니다. 빌드에는 기존 Vite CJS API와 Monaco 대형 청크 경고가 남아 있다.

## 에이전트 검토와 수정

디자이너 에이전트가 실제 Deep Dark 화면에서 중립적인 배경, 제한된 인디고 포인트, 라인 번호와 분리된 가운데 버튼, 화면 밀도를 검토했다. 중요한 시각적 이탈은 발견하지 않았다. 정지 화면 검토는 모션 판정에 사용하지 않았다.

독립 구현 검토에서 이전 비동기 결과를 현재 결과로 취급할 가능성과 긴 블록의 버튼 누락이 발견돼 회귀 테스트를 먼저 실패시킨 뒤 수정했다. 현재 테마 재선택 시 메뉴 닫힘도 수정하고 실제 클릭으로 확인했다. 최종 검증에서는 전체 복사 후 실행 취소 대상과 가장자리 버튼 크기도 수정했다.

네이티브 캡처 과정에서 완전히 숨긴 QA 창은 일부 레이어가 캡처되지 않았다. QA 창을 투명·비활성 상태로 표시해 정상 합성 후 촬영하도록 검증 도구를 수정했다. 운영 창의 표시 방식은 변경하지 않았다. 최종 PNG에서 버튼이 실제로 그려졌는지도 검사했다.
